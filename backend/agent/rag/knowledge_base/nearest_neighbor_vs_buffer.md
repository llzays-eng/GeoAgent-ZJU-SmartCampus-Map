# 最近邻检索 vs 缓冲区分析：什么时候用哪个

这两种是空间查询里最基础也最容易混用的两类操作，GeoAgent 里对应
`search_poi`（最近邻）和 `spatial_buffer`（缓冲区）两个工具。

## 最近邻检索（Nearest Neighbor）

回答的问题是"离我最近的 K 个是什么"。特点：
- 返回数量固定（比如"最近的3间自习室"），不管这3个是在50米内还是2公里外；
- 结果按距离升序排列，调用方通常只关心前几名；
- 适合"帮我找一个能去的地方"这类决策型需求——用户要的是一个可执行的答案，
  而不是完整的统计画像。

## 缓冲区分析（Buffer Analysis）

回答的问题是"某个半径范围内一共有多少个符合条件的点"。特点：
- 返回数量不固定，取决于该范围内实际有多少符合条件的点，可能是0个也可能是几十个；
- 更适合统计/评估型需求，例如"这个候选选址300米内有没有食堂和图书馆"
  ——这里关心的是"有没有""有几个"，而不是"最近的是谁"；
- 常常与属性过滤组合使用（比如"半径500米内、且noise_level=quiet的自习室"），
  因为缓冲区分析本身就是把"空间范围"和"属性条件"两个维度同时约束。

## 一个容易踩的坑

如果误用最近邻检索去回答"某范围内有多少个"这类问题，会出现"结果数量被
limit截断，掩盖了真实密度"的错误——比如范围内实际有20个茶室，但
`search_poi` 设置了 `limit=5`，只会返回5个，容易被误读成"该区域只有5个"。
反过来，如果误用缓冲区分析去回答"最近的是哪个"，当范围内数量很多时，
需要调用方自己再做一次排序截断，多了一步不必要的处理。

## 实践建议

- 用户问题里出现"最近""附近的几个""推荐一个"→ 优先用最近邻检索；
- 用户问题里出现"一共有多少""覆盖情况""周边条件对比"→ 优先用缓冲区分析；
- 拿不准时，宁可先用缓冲区分析拿到完整范围内的数据，再在这基础上排序取前几名，
  而不是反过来（最近邻检索无法还原被 limit 截断掉的信息）。
