# WGS-84 / GCJ-02 / BD-09：三套坐标系的差异与转换

本项目里充电桩数据（来自 ZJU-Charger）和其余数据（自习室、POI、建筑轮廓）
使用的坐标系不一样，是国内地图应用里一个非常典型、几乎必然会踩到的坑。

## 三套坐标系分别是什么

- **WGS-84**：国际通用的大地坐标系，GPS原始定位输出的就是WGS-84坐标。
  本项目自习室、POI、建筑轮廓、校区边界数据均直接使用WGS-84，可以
  直接叠加到OSM标准瓦片底图上。
- **GCJ-02**（"火星坐标系"）：中国国测局制定的加密坐标系，在WGS-84基础上
  加入了不可逆的非线性偏移算法。国内绝大多数地图服务（高德、腾讯地图等）
  对外接口返回的都是GCJ-02坐标，这是政策要求，不是技术选择。
- **BD-09**：百度地图自己在GCJ-02基础上又加了一层偏移算法，只有百度系
  产品使用。

## 为什么会出现偏移

WGS-84 → GCJ-02 的偏移量在国内不同地区大小不一，一般在几十米到几百米
量级，且不是简单的平移（不能用一个固定的经纬度差值去校正），而是与地理
位置相关的非线性形变。如果不做坐标系转换，直接把GCJ-02或BD-09坐标当
WGS-84用，点位在地图上会出现几十到几百米的整体"漂移"，紫金港校区这种
尺度下，偏移量可能相当于"漂移到隔壁一栋楼"。

## 本项目的实际处理方式（见 data/README.md）

充电桩数据源（ZJU-Charger）返回的坐标是 BD-09，需要按
`BD-09 → GCJ-02 → WGS-84` 两步转换才能正确叠加到项目的WGS-84底图上；
项目里这一步转换是在前端（充电桩展示逻辑）完成的，转换后坐标数组顺序
仍保持GeoJSON标准的 `[longitude, latitude]`。

对GeoAgent来说，这意味着 `query_charging_pile` 工具拿到的充电桩坐标
在返回给上层之前应确认坐标系与自习室/POI一致（均为WGS-84），否则
`spatial_buffer`/`search_poi` 里混合充电桩与其他点位计算距离时会产生
虚假的"最近"结果——这也是为什么 `agent_outputs` 里工具结果如果涉及
充电桩坐标，需要额外标注坐标系来源，而不是默认所有坐标都可以直接互相
计算距离。

## 判断坐标系的经验法则

- 如果坐标来自GPS设备原始输出、大多数遥感/GIS专业数据集：大概率WGS-84；
- 如果坐标来自高德/腾讯地图开放接口：大概率GCJ-02；
- 如果坐标来自百度地图开放接口：大概率BD-09；
- 拿不准时，最可靠的办法不是猜，而是把同一个点位分别用不同坐标系假设
  画在底图上做视觉比对，偏移几十到几百米的那个通常就是用错了坐标系。
