# Haversine 公式：球面距离计算原理与适用范围

GeoAgent 里几乎所有空间查询（`search_poi`、`spatial_buffer`、`query_charging_pile`
的按距离排序）最终都要算"两个经纬度坐标之间的距离是多少米"，用的就是 Haversine 公式。

## 为什么不能直接用平面距离公式

经纬度坐标 (lon, lat) 是球面坐标，如果直接套用平面几何的欧氏距离
`sqrt((lat1-lat2)^2 + (lon1-lon2)^2)`，会有两个问题：

1. 单位不统一：纬度每变化1度对应的实际距离约等于111km，但经度每变化1度
   对应的实际距离会随纬度变化（赤道附近约111km，越靠近两极越短，按
   `111km × cos(纬度)` 衰减）。紫金港校区纬度约30.3°N，同样1度经度对应的
   实际距离比1度纬度短约13.7%，直接平方相加会systematically算错方向权重。
2. 忽略地球曲率：范围小的时候（比如校园尺度，几公里内）曲率影响不明显，
   但公式本身不是为球面设计的，误差来源不可控。

## Haversine 公式

给定两点 (lat1, lon1) 和 (lat2, lon2)（弧度制），球面距离：

```
a = sin²(Δlat/2) + cos(lat1)·cos(lat2)·sin²(Δlon/2)
c = 2·atan2(√a, √(1−a))
distance = R · c        # R = 地球平均半径 ≈ 6,371,000 米
```

这是本项目 `geo_data.haversine_m()` 的实现方式，代码里用 `asin` 而不是
`atan2` 是等价的化简写法（因为 a 恒在 [0,1] 区间内）。

## 适用范围与局限

- 校园尺度（几公里内）用 Haversine 已经足够精确，业内一般认为误差在
  0.5%以内，实测层面可以忽略；
- 如果需要更高精度（比如厘米级测绘），应该用椭球模型（如 Vincenty 公式或
  直接用有精确大地基准的投影坐标系），Haversine 假设地球是理想球体，
  不是椭球；
- Haversine 只算"直线距离"（大圆距离），不代表实际步行/骑行路径长度——
  本项目明确不做路线规划，这里的距离只用于"哪个更近"的排序和范围判断，
  不能理解为可达性或步行时间。
